# themify — architecture

Imported from [Aejkatappaja/dotfiles](https://github.com/Aejkatappaja/dotfiles) (WTFPL).
This is the map of how the whole machine fits together, kept here so we can
extend it without reverse-engineering it again.

> The live copy still runs from `~/.config/bin/` until this package is stowed.
> Stow it with: `stow --target ~ theme` (after moving the original away).

## The four layers

```
┌─────────────────────────────────────────────────────────────────┐
│ ENGINE    .config/bin/themify      bash, ~220 lines, stateless  │
│           knows HOW to apply colors; never changes per-theme    │
├─────────────────────────────────────────────────────────────────┤
│ DATA      .config/bin/themes/*.conf   one file per theme —      │
│           pure color roles, tool-agnostic:                     │
│           BG/BG_ALT/BG_SEL/FG/FG_MUTED/BORDER/ACCENT/          │
│           ACCENT_2/ERROR/WARN/OK/INFO                                   │
├─────────────────────────────────────────────────────────────────┤
│ ARTIFACTS per-theme assets the targets point at:                │
│           ghostty/themes/{sora,cendre} — GENERATED by build.sh │
│           sketchybar/colors.lua palette tables (both themes     │
│           embedded; selector flips which one is exposed)        │
│           lazygit/yazi/hunk/fzf per-theme variant files         │
│           (dormant on this machine — files absent)              │
├─────────────────────────────────────────────────────────────────┤
│ TARGETS   the config files the engine edits (anchor-based):     │
│           ghostty/config, tmux/tmux.conf, borders/bordersrc,    │
│           sketchybar/colors.lua, ~/.gitconfig, …                │
└─────────────────────────────────────────────────────────────────┘
```

## Execution flow (`themify sora`)

```
1  glob themes/*.conf            → [cendre, sora]
2  target = argument, else interactive picker
   (gum → fzf → numbered menu; no tty → usage error, exit 1)
3  source themes/<target>.conf   → role vars in memory
3b engine derives tool formats: tmux mode-style, borders
   ACCENT→ACCENT_2 gradient, …; non-color references use the theme name by
   convention (artifact names == theme name)
5  sketchybar  sed theme line    → sketchybar --reload      LIVE
6  tmux        sed 3 anchors     → tmux source-file         LIVE
7  ghostty     sed theme =       → osascript ⌘⇧,            LIVE
8  pi          sed theme line    →                          NEXT LAUNCH
8  borders     sed active_color  → push to daemon           LIVE
9  nvim        sed colorscheme   → --remote-expr per socket LIVE
10 vim/bat/btop/yazi/lazygit/…   → file edit only           NEXT LAUNCH
11 obsidian    sed cssTheme      →                          RESTART
12 wallpaper   cp variant → current-theme.jpg, killall      LIVE
```

## The two mechanisms

**Anchor edits** (line-surgical, for tools with one config):
`anchor <regex> <file> <label>` greps first; missing file or missing pattern
→ warn + skip (never crashes, tools are independent). Then `sed -i ''` swaps
exactly that line. Idempotent: re-running the same theme rewrites same values.

**Variant swaps** (whole-file, for tools needing more than a line):
`cp themes/<tool>/<PALETTE>.<ext>` over the active file. Used for yazi, hunk,
lazygit, fzf.

## Safety features

- `set -euo pipefail` — unexpected failure stops rather than half-applies
- every target optional — absent files only produce `⚠` warnings
- borders daemon check (`pgrep -x borders`) — without a running daemon,
  `borders <arg>` *becomes* the daemon with a one-arg config; must not call it
- empty `WALLPAPER=` skips the wallpaper step entirely
- ghostty reload assumes the `cmd+shift+comma = reload_config` keybind exists
  (it does — see ghostty package)

## Palette data model (colors.lua)

Each theme defines three semantic layers, not just 16 raw colors:

- **base** — black/white/red/green/blue/yellow/orange/magenta/grey/shadow
- **accent** — named pigments (cyan/purple/sage/rose/gold/peach/teal/steel)
  plus `primary` (the bar's own accent)
- **semantic** — error/warn/ok/info for status widgets (deliberately more
  chroma than syntax colors, so a failing widget never wears a keyword's red)
- **surfaces** — bar bg/border, popup bg/border, bg1/bg2
- `with_alpha(color, a)` — runtime alpha helper for the Lua side

## Known gaps / improvement backlog

1. **fonts not managed**: colors only. Candidates for a fonts layer:
   ghostty (Google Sans Code), sketchybar (SF Pro via helpers/default_font),
   nerd-font fallbacks (Hack/JetBrainsMono casks exist).
2. **`~/.config/bin` not on PATH** — `themify` only works via Raycast or full
   path. Add to PATH in zsh package (S12).
3. ~~palette duplication~~ RESOLVED: sketchybar reads the conf at runtime
   (pure renderer, S11) and ghostty themes are GENERATED by `build.sh`
   (ANSI_0–15 roles in the conf; run after editing a theme, output committed).
   Every color in the setup now lives in exactly one place: `themes/*.conf`.
4. **dormant targets**: nvim, bat, btop, yazi, hunk, lazygit, fzf, wallpapers,
   obsidian, opencode (deleted — unused). Engine handles
   absence gracefully; artifacts exist upstream if ever adopted.
